# v2.1 Workflow Hardening

**Status:** Active

## Goal

Make the completed v2 workflow resilient and efficient for repeated real-world
hunts without expanding into automated market research.

## Implemented baseline

The current code already includes:

- **Stable upload fingerprint:** deterministic uploaded-file fingerprints keep
  the same hunt session and candidate state across ordinary Streamlit reruns.
- **Gemini 503 retry/backoff:** `503` / `UNAVAILABLE` failures receive four
  primary attempts with approximate 2, 5, and 10 second delays plus jitter.
- **Fallback model:** after primary transient retries are exhausted, the
  configured `CARD_HUNT_FALLBACK_MODEL` is attempted once.
- **Crop failure isolation:** a failed crop records an error without clearing its
  previous candidate result or unrelated session state.
- **Retry UI:** users can identify one selected crop and retry crops with recorded
  AI errors.
- **Raw usage display:** available per-response Gemini usage fields are retained
  and shown as session rows in the Audit / Export tab.

## Remaining scope

- **Appropriate 429/transient handling:** classify supported rate-limit and other
  genuinely transient provider failures, honor retry guidance when available,
  and avoid retrying invalid, authentication, schema, or programming errors.
- **Identify Unresolved:** run batch identification only for candidates that have
  not succeeded or still require resolution, without overwriting confirmed work.
- **Inline Confirm / Correct / Retry:** put the primary review actions beside each
  crop and make their state transitions explicit and auditable.
- **Better crop selector/preview:** make it easier to select, inspect, and compare
  the tight crop, padded context, and candidate details before an AI action.
- **Session summary:** show progress and counts for detected, identified,
  unresolved, needs-review, verified, eligible, failed, and purchased candidates.
- **Resumable hunts:** load a saved hunt and reconnect it safely to persisted crop
  context without resetting unrelated active data.
- **Duplicate purchase protection:** prevent accidental repeated ledger entries
  for the same hunt candidate while allowing an intentional override path.
- **Persistent workflow navigation:** keep the user's active workflow view across
  reruns and recovery actions instead of returning them to an unrelated view.
- **Aggregated API usage summary:** summarize calls and available token fields by
  provider/model/session while retaining access to raw per-call rows.

## Exit criteria

- Supported `429` and temporary provider failures follow a bounded, auditable
  retry policy; permanent request/auth/schema failures fail immediately.
- Users can identify unresolved candidates without replacing successful or
  manually confirmed results.
- Confirm, Correct, and Retry actions are available in crop context and preserve
  exact-ID gate semantics.
- Crop selection and preview clearly show the image context being reviewed or
  sent to Gemini.
- Session summary counts remain correct across reruns and partial failures.
- A saved hunt can be resumed with its candidate and crop context intact.
- Repeating a purchase action cannot silently duplicate an existing ledger row.
- Workflow navigation remains stable across normal Streamlit reruns.
- Aggregated usage reconciles with the raw usage rows when Gemini exposes token
  metadata.
- Offline automated tests cover critical state, retry, resume, duplicate, and
  gate behavior; the manual release checklist passes with disposable data.

## Non-blocking quality track

Exact-print identification accuracy, crop heuristics, prompts, schemas, and model
evaluation continue throughout v2.1 and later milestones. They must remain
conservative, but completing a tuning campaign is not an exit criterion for v2.1
and does not block v3 market-snapshot work.
